# Async-first Q3 initiative prioritization

**Session type:** Async-first distributed convergence  
**Scale:** 12 participants · US / EU / APAC  
**Duration:** 3 calendar days async (Miro) + 90-minute live convergence call  
**Mode:** Online-only

---

## Goal

From **pre-submitted Q3 initiative ideas**, produce a **ranked top-priority list for Q3** with owners, explicit deprioritizations, and documented criteria — using async board work for review and scoring, and a single 90-minute live call for convergence only (not live brainstorming).

## Decision authority

- **Sponsor / decision owner:** Product or engineering leadership lead (assumed present on live call; name before kickoff).
- **Decision rule:** Consult → **consent on priorities** using [Gradients of Agreement](https://workshopweaver.com/facilitation-methods/gradients-of-agreement) for the ranked list; sponsor confirms final Q3 commitment at close.
- **Authority reality:** This group can recommend and commit **within known Q3 capacity**; sponsor may adjust scope after the session but commits to publishing the decision log within 48 hours. If capacity constraints were not pre-shared, treat live session as **alignment on ranking** with sponsor sign-off — not open-ended scope expansion.
- **Confidentiality:** Internal only; **attributed** contributions on the Miro board (participants are accountable stakeholders). Live call **not recorded** unless explicitly agreed at open; async board history retained for audit.

## Key outcomes

- Shared prioritization criteria visible before any voting
- Every pre-submitted idea reviewed async; duplicates merged; gaps noted (no live ideation)
- Ranked **top 3–5 Q3 initiatives** with single owners and one success signal each
- Explicit **"not in Q3"** list with rationale
- Decision log with criteria, vote counts, and gradients-of-agreement reservations
- First progress checkpoint **booked on calendar** before live call ends

## Acceptance criteria

- **Done:** Criteria agreed (≥4 dimensions); all pre-submitted ideas scored or explicitly parked; top priorities have named owners who confirm authority on live call; "not doing" list published; sponsor confirms or revises within 48h.
- **Fallback if live convergence stalls:** Publish async vote results as **provisional ranking**; sponsor holds 30-minute decision brief within 5 business days; unresolved items go to parking lot with owner.

## Per-block detail

### Block: Launch and frame [async] (Day 1)

**Why:** Twelve distributed participants need a shared question, board rules, and criteria draft before touching pre-submitted ideas — async so every timezone can read and react without a live kickoff.

**Format:** [ToP Focused Conversation](https://www.top-network.org/use-focused-conversation) (async written prompts) + plain facilitation structure

**Board / frame (ASCII):**
```
┌──────────────────────────────────────────────────────────────┐
│  MIRO — Q3 PRIORITY CONVERGENCE                              │
├──────────────────────────────────────────────────────────────┤
│  ZONE A: CHARTER                                             │
│  • Decision question                                         │
│  • Async deadlines (Day 1 / 2 / 3 EOD in your TZ)            │
│  • Rule: NO new ideas — review & score pre-submitted only    │
├──────────────────────────────────────────────────────────────┤
│  ZONE B: CRITERIA (draft → refine Day 2)                     │
│  [ Impact ] [ Effort ] [ Strategic fit ] [ Risk ] [ +? ]     │
├──────────────────────────────────────────────────────────────┤
│  ZONE C: PRE-SUBMITTED IDEAS (read-only cards)               │
│  [ Idea 1 ] [ Idea 2 ] [ Idea 3 ] ...                        │
├──────────────────────────────────────────────────────────────┤
│  ZONE D: PARKING LOT                                         │
└──────────────────────────────────────────────────────────────┘
```

**Facilitator instruction:** Post charter before Day 1 start. Pin: "We are **prioritizing**, not brainstorming — add comments and scores, not new initiative cards." Send calendar holds for async deadlines and live call. Ask each participant to reply in Zone A with: (1) one sentence on what Q3 success looks like, (2) one criterion they'd add or challenge. Facilitator synthesizes criteria replies into Zone B by Day 2 open.

**Facilitator contingencies:**

| If… | Then… |
| --- | --- |
| Someone adds new idea cards | Move to Parking Lot; remind charter in Slack; do not merge into scoring |
| Low Day 1 engagement | DM non-responders; extend Day 1 deadline 12h; do not proceed to live without ≥9/12 async touch |
| Criteria conflict | Facilitator proposes 4–6 criteria max; async dot vote on criteria Day 2 morning |
| APAC can't meet live window | Offer brief async comment window on live outcomes; record decisions in board only (no recording) |

**Timed flow (facilitator async cadence):**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 30 min | Publish board; send kickoff message with links and deadlines |
| 2 | EOD Day 1 | Nudge non-responders; snapshot criteria comments |
| 3 | Day 2 AM | Publish synthesized criteria draft in Zone B |

**Block output:** Charter pinned; criteria draft; participation tracker (private).

### Block: Review pre-submitted ideas [async] (Day 1–2)

**Why:** Pre-submitted ideas need equal async review and light enrichment before scoring — especially for quieter APAC/EU voices who won't dominate a live call.

**Format:** [Brainwriting](https://www.sessionlab.com/methods/brainwriting) (comment-only, no new ideas) + plain facilitation structure

**Board / frame (ASCII):**
```
┌──────────────────────────────────────────────────────────────┐
│  Each IDEA CARD:                                             │
│  ┌────────────────────────────────────────┐                  │
│  │ Title · Submitter · 2-line summary     │                  │
│  │ Pre-read link (if any)                 │                  │
│  ├────────────────────────────────────────┤                  │
│  │ COMMENTS (brainwriting — one per person) │                  │
│  │ • Clarifying question                  │                  │
│  │ • Dependency / risk flag               │                  │
│  │ • Duplicate of → [card ID]           │                  │
│  └────────────────────────────────────────┘                  │
└──────────────────────────────────────────────────────────────┘
```

**Facilitator instruction:** One comment sticky per person per idea (max 12 stickies per card). Prompt: "Clarify, flag risk, or link duplicate — do not propose new initiatives." Facilitator merges obvious duplicates overnight Day 1→2; marks merged cards read-only. Submitter may reply once to clarifications.

**Facilitator contingencies:**

| If… | Then… |
| --- | --- |
| Idea count >15 | Group low-similarity items; defer deep comment on bottom third to async dot only |
| Dominant async commenter | Cap at one sticky per idea; invite others by name in Slack |
| Missing submitter context | Facilitator adds 2-line summary from pre-read; tag submitter to confirm |

**Timed flow:**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | Day 1 | Open comment columns on all cards |
| 2 | Day 1 EOD | Merge duplicates; post merge log |
| 3 | Day 2 AM | Remind: scoring opens after comments close Day 2 noon UTC |

**Block output:** Enriched idea cards; duplicate merge log; comment completion ≥75% target.

### Block: Score against criteria [async] (Day 2)

**Why:** Individual scoring before live prevents loudest-voice wins; Importance/Difficulty plus budget constraint surfaces trade-offs early.

**Format:** [Importance/Difficulty Matrix](https://www.luma-institute.com/importance-difficulty-matrix/) + [Buy a Feature](https://www.luma-institute.com/buy-a-feature/)

**Board / frame (ASCII):**
```
┌──────────────────────────────────────────────────────────────┐
│  ZONE: 2×2 MATRIX (facilitator view — aggregate after)     │
│         High impact                                          │
│              │    QUICK WINS    │    BIG BETS               │
│              │                  │                           │
│  Low effort ─┼──────────────────┼───────────────── High    │
│              │    FILL-INS      │    MONEY PITS             │
│              │                  │         effort            │
├──────────────────────────────────────────────────────────────┤
│  ZONE: BUY-A-FEATURE (per person — private frame or row)   │
│  Budget: 100 points · allocate across ideas · min 5 on ≥3  │
└──────────────────────────────────────────────────────────────┘
```

**Facilitator instruction:** **Criteria before scoring:** post locked criteria list at block open. Each person places **one dot** per idea on the matrix (use Miro private mode or named rows). Then allocate 100 points across ideas (Buy a Feature). Facilitator publishes **aggregate heatmap only** — not individual ballots — before Day 3 clustering.

**Facilitator contingencies:**

| If… | Then… |
| --- | --- |
| <8 people score | Extend scoring 12h; live call still proceeds with noted gap |
| Scores wildly diverge on one idea | Flag for live discussion; prepare 2-sentence pro/con summary |
| Criteria disputed mid-scoring | Pause scoring; 24h async criteria dot vote; resume |

**Timed flow:**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 15 min | Post criteria lock + scoring instructions |
| 2 | Day 2 | Monitor completion; answer clarifications in Slack |
| 3 | Day 2 EOD | Publish aggregate matrix + budget totals |

**Block output:** Aggregate importance/difficulty map; budget-weighted ranking draft; outliers flagged for live.

### Block: Cluster and async pre-vote [async] (Day 3)

**Why:** Facilitator synthesis reduces live cognitive load; async dot vote gives the live session a defensible starting shortlist.

**Format:** [Affinity Clustering](https://www.luma-institute.com/affinity-clustering/) + [Dot Vote](https://designsprintkit.withgoogle.com/methodology/phase4-decide/dot-vote)

**Board / frame (ASCII):**
```
┌──────────────────────────────────────────────────────────────┐
│  CLUSTERS (facilitator-built from matrix + comments)         │
│  [ Theme A: … ]  [ Theme B: … ]  [ Theme C: … ]              │
├──────────────────────────────────────────────────────────────┤
│  ASYNC PRE-VOTE (3 dots per person · on themes OR top ideas) │
│  Live will start from top 5 by dot count                     │
└──────────────────────────────────────────────────────────────┘
```

**Facilitator instruction:** Cluster ideas into 4–7 themes OR carry forward top ~8 ideas by aggregate score — pick one approach and state it in the charter. Async dot vote: **3 dots per person**, must spread across at least 2 items. Publish ranked shortlist with vote counts by Day 3 EOD. Send pre-read to live participants: shortlist + criteria + "come ready to confirm or challenge, not pitch new ideas."

**Facilitator contingencies:**

| If… | Then… |
| --- | --- |
| Clusters unclear | Skip thematic clustering; pre-vote on top 8 ideas by score only |
| Tie for 5th place | Carry 6 items into live; cut list handles trim |
| Zero async pre-votes | Use aggregate Buy a Feature ranking as live starting point |

**Timed flow:**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | Day 3 AM | Publish clusters / shortlist |
| 2 | Day 3 | Run async dot vote; remind live time + timezone |
| 3 | Day 3 EOD | Publish ranked top 5–6 + pre-read pack |

**Block output:** Cluster map; async vote results; live pre-read sent.

### Block: Confirm criteria and authority [live] (0:05–0:12)

**Why:** Live vote is invalid without locked criteria and explicit decision rule — especially with sponsor present.

**Format:** [Agreement and Certainty](https://www.liberatingstructures.com/agreement-and-certainty) + plain facilitation structure

**Board / frame (ASCII):**
```
┌──────────────────────────────────────────────────────────────┐
│  CRITERIA (locked)          │  DECISION RULE                 │
│  1. …                       │  Consult → ranked list         │
│  2. …                       │  Gradients on final list       │
│  3. …                       │  Sponsor confirms Q3 scope     │
└──────────────────────────────────────────────────────────────┘
```

**Facilitator instruction:** Read criteria aloud once. Ask: "Any blocking objection to using these criteria today?" — brief thumbs, not debate. Sponsor states in one sentence how today's output becomes Q3 plan. Redirect new ideas to parking lot.

**Facilitator contingencies:**

| If… | Then… |
| --- | --- |
| Criteria challenge | 3-minute max amendment; else defer to sponsor offline |
| Sponsor absent | Proceed as provisional ranking; book sponsor sign-off within 48h |
| New idea pitched live | Park; "Async charter was review-only" |

**Timed flow:**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 2 min | Display criteria + async results |
| 2 | 3 min | Confirm criteria; sponsor speaks |
| 3 | 2 min | Agreement/Certainty: place Q3 prioritization on matrix |

**Block output:** Locked criteria on screen; sponsor commitment line in notes.

### Block: Converge on top priorities [live] (0:12–0:35)

**Why:** Live time focuses on resolving ties, validating owners, and debating trade-offs among pre-voted options — not generating options.

**Format:** [ToP Collaborative Priority Setting](https://www.top-network.org/set-priorities-collaboratively) + [Dot Vote](https://designsprintkit.withgoogle.com/methodology/phase4-decide/dot-vote)

**Board / frame (ASCII):**
```
┌──────────────────────────────────────────────────────────────┐
│  SHORTLIST (from async)     │  LIVE ADJUSTMENT               │
│  1. [idea] (async votes)    │  ▲ move up / ▼ move down       │
│  2. …                       │  Owner: ______                 │
│  3. …                       │  Success signal: ______        │
│  4. …                       │                                │
│  5. …                       │                                │
└──────────────────────────────────────────────────────────────┘
```

**Facilitator instruction:** **Criteria before any re-vote:** restate criteria in 30 seconds. Discuss top 6 only — 2 minutes max per contested item. If re-vote needed, use **1 dot each** on Miro in 60 seconds. Assign **provisional owner** per top item; owner confirms aloud or names delegate.

**Facilitator contingencies:**

| If… | Then… |
| --- | --- |
| Debate spirals | Timebox; "hold tension" note; move to parking lot |
| Owner declines | Sponsor assigns or item drops |
| Split vote | Use async pre-vote as tiebreak unless new info surfaced |

**Timed flow:**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 3 min | Present async shortlist |
| 2 | 15 min | Facilitated discussion on contested ranks 3–6 |
| 3 | 3 min | Optional live dot if needed |
| 4 | 2 min | Confirm top 3–5 + owners |

**Block output:** Ranked priority list with owners on board.

### Block: Trade-offs and deprioritize [live] (0:40–0:55)

**Why:** A priority list without explicit cuts is a wish list; force "not in Q3" with rationale.

**Format:** [What, So What, Now What](https://www.liberatingstructures.com/what-so-what-now-what)

**Board / frame (ASCII):**
```
┌──────────────┬──────────────┬──────────────┐
│    WHAT      │   SO WHAT    │  NOW WHAT    │
│  (cut list)  │  (impact)    │  (defer/when)│
├──────────────┼──────────────┼──────────────┤
│  Idea X      │              │  Q4 / never  │
│  Idea Y      │              │  needs data  │
└──────────────┴──────────────┴──────────────┘
```

**Facilitator instruction:** WHAT: list ideas **not** in top 3–5 (from full pre-submit set). SO WHAT: one sentence impact of not doing. NOW WHAT: defer date or condition for revisit. Sponsor may add capacity reality in SO WHAT column.

**Facilitator contingencies:**

| If… | Then… |
| --- | --- |
| Pushback on cuts | Document dissent; item goes to parking lot with review date |
| "We can do everything" | Sponsor names capacity constraint; re-run top-N count |

**Timed flow:**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 5 min | WHAT — scribe lists non-prioritized ideas |
| 2 | 5 min | SO WHAT — round-robin one line each on top 3 cuts |
| 3 | 5 min | NOW WHAT — assign defer owner or quarter |

**Block output:** "Not in Q3" column populated with rationale.

### Block: Commit and reservations [live] (0:55–1:25)

**Why:** Owners and success signals make priorities actionable; gradients capture reservations without false consensus.

**Format:** [Open Items List](https://retromat.org/en/?id=24) + [Gradients of Agreement](https://workshopweaver.com/facilitation-methods/gradients-of-agreement)

**Board / frame (ASCII):**
```
┌──────────────────────────────────────────────────────────────┐
│  Q3 COMMITMENTS                                              │
│  Priority │ Owner │ Success signal │ First milestone │ Due  │
├──────────────────────────────────────────────────────────────┤
│  GRADIENTS (1–8) per priority — name + level if ≤5           │
└──────────────────────────────────────────────────────────────┘
```

**Facilitator instruction:** Each owner states success signal and first milestone (30 sec each). Then gradients poll on **the full ranked list**: "Can you live with this Q3 set?" — 1–8 in chat or Miro. Capture level 1–3 reservations verbatim. Sponsor confirms list or names what changes offline.

**Facilitator contingencies:**

| If… | Then… |
| --- | --- |
| Owner lacks authority | Sponsor reassigns before close |
| Multiple level 1–2 gradients | Document; sponsor addresses top reservation live or schedules 1:1 |
| Over time | Cut gradient discussion to top 3 priorities only |

**Timed flow:**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 10 min | Open Items List — owners + milestones |
| 2 | 10 min | Gradients of Agreement on full set |
| 3 | 8 min | Capture reservations; sponsor closing line |
| 4 | 2 min | Verify owner authority aloud |

**Block output:** Commitment table; gradient snapshot; reservation log.

**Facilitator instruction:** Recap: top priorities, not-doing list, sponsor next step. Confirm **mid-Q3 checkpoint date** already on calendar (book during live if not). Thank async contributors.

**Timed flow:**

| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 2 min | Read back decisions |

## Cut list

If running long:

- **Cut:** Live re-vote (use async pre-vote as final); gradient discussion beyond top 3 priorities; per-idea live debate beyond 2 minutes; full WHAT/SO WHAT on all deprioritized items (top 5 cuts only).
- **Protect:** Criteria confirmation; ranked top 3–5 with owners; "not in Q3" list (at least top 5 deferred); Open Items List + sponsor confirmation line; **checkpoint date booked**.

If async participation is weak (<8/12):

- **Cut:** Thematic clustering; proceed with facilitator ranking from Buy a Feature scores only.
- **Protect:** Live criteria lock; owner assignment; written provisional ranking if live quorum <9.

## Hybrid / online parity

**Digital board:** Miro — **single source of truth** for all async and live work. Rule: **If it's not on the board, it didn't happen.**

**Online group:** All 12 join via individual screens. Async work is inherently equal; live call uses Miro for votes (not show of hands on video). Chat for gradients and checkout.

**Parity rules:**

- One person = one screen — no co-located sub-groups
- Async deadlines stated in **UTC and local examples** (US / EU / APAC)
- Votes and scores on Miro, attributed
- Speaking order: **APAC and EU first** in live discussion (they joined outside local business hours more often)

**Co-facilitation:** Online advocate monitors chat and participation; scribe updates board in real time during live blocks.

**Online operations checklist:**

- [ ] Miro permissions tested; all 12 can comment and vote
- [ ] Video link + Miro link in single calendar invite
- [ ] Backup: dial-in + phone hotspot note in invite
- [ ] Async reminder bot or scheduled Slack messages (Day 1/2/3)
- [ ] Screen share tested; facilitator can show aggregate results without exposing private scoring rows
- [ ] Break timer visible; 5-minute break at 0:35
- [ ] Dedicated online advocate assigned for live call
