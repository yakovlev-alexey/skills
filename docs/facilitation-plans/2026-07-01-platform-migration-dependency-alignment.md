# Platform Migration — Cross-Team Dependency Alignment

## Goal

Align 20 participants (14 in-room, 6 online) over 3 hours on cross-team dependencies, constraints, and sequencing for the platform migration — producing explicit ownership, cross-team requests, and sequenced commitments.

## Decision authority

- **Sponsor:** Platform migration lead (must be present or delegate with commit authority).
- **Decision rule:** Consult + documented commitments; teams confirm what they can own.
- **Acceptance criteria:** Dependency map with owners; cross-team asks captured; sequenced next steps with dates. **Fallback:** Input-gathering only if key owners missing.

## Key outcomes

- Shared dependency question and success signal
- Visible ownership map and handoff gaps
- Team-owned vs external blockers separated
- Cross-team requests ([What I Need From You](https://www.liberatingstructures.com/what-i-need-from-you))
- Sequenced commitments with owners and dates

**Participation structure (20 people):** 4 in-room tables (~3–4 each) + **6 online in 2 remote breakouts (3 each)** — **not** one isolated "online table."

### Block: Frame (0:00-0:15)

**Why:** Dependency alignment needs a shared question — not open brainstorm.

**Format:** [ToP Focused Conversation](https://www.top-network.org/use-focused-conversation)

**Facilitator instruction:** Objective → reflective → interpretive → decision framing on migration dependencies.

**Timed flow:**
| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 4 min | Objective: migration context |
| 2 | 4 min | Reflective: concerns |
| 3 | 4 min | Interpretive: dependency definition |
| 4 | 3 min | Decision: success signal |

**Block output:** Shared question on Miro

---

### Block: Map dependencies (0:15-0:45)

**Why:** Make ownership and handoffs visible before negotiating requests.

**Format:** [Responsibility Mapping](https://leanpub.com/visualcollaborationtools)

**Board / frame (ASCII):**
```
┌─────────────┬─────────────┬─────────────┐
│  Team/System│  Owns       │  Depends on │
├─────────────┼─────────────┼─────────────┤
│             │             │             │
└─────────────┴─────────────┴─────────────┘
```

**Facilitator instruction:** Tables map their slice; online breakouts map in parallel; **dedicated remote facilitator** supports online groups.

**Timed flow:**
| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 5 min | Instructions; assign tables/breakouts |
| 2 | 22 min | Parallel mapping |
| 3 | 8 min | Gallery walk on Miro |

**Block output:** Responsibility map on Miro

---

### Block: Constraints (0:45-1:15)

**Why:** Separate fixable team levers from organizational blockers.

**Format:** [Circles & Soup / Circle of Influence](https://retromat.org/en/?id=29)

**Timed flow:**
| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 3 min | Explain circles |
| 2 | 22 min | Table/breakout sort |
| 3 | 5 min | Top blockers to plenary |

**Block output:** Constraints map

### Block: Break (1:15-1:25)

**Why:** Mandatory break in 3-hour session.

### Block: Cross-team requests (1:25-1:55)

**Why:** Make asks negotiable and explicit across teams.

**Format:** [What I Need From You](https://www.liberatingstructures.com/what-i-need-from-you)

**Facilitator instruction:** Pairs/triads across team boundaries where possible; online pairs include at least one remote participant per pair via Miro + Zoom.

**Timed flow:**
| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 5 min | Pair formation (cross-team, cross-mode) |
| 2 | 20 min | WINFY rounds |
| 3 | 5 min | Capture on board |

**Block output:** Request/offer cards on Miro

---

### Block: Sequence commitments (1:55-2:35)

**Why:** Dependencies need dates and minimum specs, not vague agreement.

**Format:** [Open Items List](https://retromat.org/en/?id=24) + [Min Specs](https://www.liberatingstructures.com/min-specs)

**Timed flow:**
| Step | Time | Facilitator action |
| --- | --- | --- |
| 1 | 5 min | Draft sequence on board |
| 2 | 25 min | Table delegates negotiate dates |
| 3 | 10 min | Min Specs for top 3 commitments |

**Block output:** Sequenced action table

---

### Block: Report-out + close (2:35-3:00)

**Why:** Confirm commitments; book checkpoint before end.

**Timed flow:**
| Step | Time | Facilitator action |
| --- | --- | --- |

**Block output:** Confirmed commitments + calendar hold

## Cut list

If running long:
- **Cut:** Gallery walk depth; reduce Min Specs to top 2 items; shorten report-outs to written async
- **Protect:** Frame, dependency map, cross-team requests, sequenced owners, checkpoint booking

## Preparation

**Space / tools:** Room with 4 tables; Miro as single source of truth; Zoom with breakout rooms; **1 person = 1 screen** in room (laptops open to Miro)

**Pre-read / pre-work:** Migration overview + known dependency list sent 48h ahead; each team pre-fills one row on Miro

**Facilitator role:** Lead facilitator (in-room); **dedicated remote facilitator** (required); table hosts; scribe on Miro

**Parking lot:** Out-of-scope feature debates → separate product forum

## Hybrid / online parity

**Digital board:** Miro — single source of truth for all capture, voting, and sequence

**Online group:** 6 remotes in **2 breakouts of 3** — paired with in-room table partners via shared Miro zones; **avoid "one online table"** isolating all remotes together without in-room partners

**Parity rules:**
- If it's not on Miro, it didn't happen
- Online speakers first in plenary report-outs
- Individual dot-votes on Miro, not show of hands in room
- In-room participants use **their own laptop** to Miro (1 person = 1 screen)

**Co-facilitation:** Remote facilitator monitors chat, hands, breakout timing, reads room-only comments into Miro

**Hybrid operations checklist (REQUIRED):**
- [ ] AV rehearsal completed; room mic/speaker layout tested; remote audio check
- [ ] Crosstalk plan: one speaker at a time; mute when not speaking
- [ ] Backup channel documented (Slack thread + phone bridge if Zoom fails)
- [ ] Remote access checks completed before session (Miro guest links, Zoom breakouts)
- [ ] Breakout architecture parity — in-room tables paired with remote breakouts via shared Miro frames; **not** one isolated online table
- [ ] **1 person = 1 screen** — even in-room participants on Miro individually
- [ ] **Dedicated remote facilitator assigned** for full session
